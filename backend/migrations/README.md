Schema v1: users, audit, datasets (JSON write sequence), configs (bounded LSM parameters), trials (immutable input snapshot and JSON result). MySQL stores metadata only. Run python -m scripts.seed_demo for create-if-missing and natural-key seed; existing values are not overwritten.

Schema v2 (online key-range migration rehearsal): migrations (route map, copy cursor/checkpoint, switch watermark, event history), shards (source shards plus one target shard per migration), shard_versions (per-key versions including tombstones, unique on shard+key+seq, key columns use utf8mb4_bin so range order is bytewise), migration_writes (append-only acknowledged-write log used as the query Oracle and as evidence for writes before/after switch). Version and shard simulation is still a Python teaching model; MySQL persists the metadata. `Base.metadata.create_all` adds the new tables on startup; there is no in-place alter of the v1 tables, so existing datasets/configs/trials keep working unchanged.
